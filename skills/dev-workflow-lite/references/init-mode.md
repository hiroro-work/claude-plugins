# Init mode

Read from `SKILL.md` § Mode detection when `--init` is passed. This mode writes settings and a project `run-tests` skill, then ends the session's work; nothing it generates is usable until the next session.

1. **Detect** the project type from `package.json`, `Gemfile`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `Makefile`; the package manager from lock files (JS/TS); and the static checks to run as `check_commands` (lint, format, typecheck). For TypeScript, look at `tsconfig*.json` at the root only, drop names that signal a non-typecheck role (`tsconfig.eslint.json`, `tsconfig.*.test.json`), read the root `tsconfig.json` as JSONC, and emit one typecheck command per remaining tsconfig; when the root has a non-empty `references` array, emit commands for the referenced leaves instead of the root.
2. **Detect prerequisites** for tests: a Docker daemon and services, Rails `db:prepare`, a `bin/setup` or `script/setup` script (preferred as the single setup command), a `.env.example` (manual guidance only).
3. **Ask** which reviewer skill to use (default `ask-peer`), then present the detected commands, test approach, prerequisites, and reviewer for confirmation (USER GATE).
4. **Write `.claude/dev-workflow.md`** on approval. Read the existing file first and preserve keys this mode does not manage (for example `hooks`); on malformed YAML ask whether to overwrite or abort. Always set `test_commands: ["Skill(run-tests)"]`.
5. **Generate `.claude/skills/run-tests/SKILL.md`** unless one exists that already matches this shape. Frontmatter: `name`, `description`, `allowed-tools` (`Agent`, `Bash(git diff *)`, the detected test commands, the prerequisite commands). Body: an optional Prerequisites section (only when detected); a Process that (i) runs prerequisite checks with setup and a retry poll up to 30 seconds, (ii) scopes tests from `--base-commit <sha>` via `git diff --name-only <sha>` (else `HEAD`), running targeted tests for localized changes and the whole suite otherwise, (iii) spawns an `Agent` with `model: sonnet` to run the detected test commands, (iv) returns the subagent's summary; and a three-status return contract SUCCESS / TEST_FAILED / EXECUTION_ERROR, where EXECUTION_ERROR means an infrastructure or prerequisite failure rather than a failing test.
6. **Verify**: run each `check_commands` entry and report pass or fail; run the generated skill's test commands directly once and report in the three-status form. Failures are reported with suggested fixes and do not block.
7. Tell the user the generated skill is recognized from the next session, so `/dev-workflow-lite <task>` should wait for a new session.
