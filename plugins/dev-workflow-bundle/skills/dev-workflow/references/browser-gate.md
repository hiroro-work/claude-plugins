# Plan review in the browser

Read from `SKILL.md` Phase 5 (Plan Approval) when the browser gate runs, and from `plan-artifact.md` § Team-review gate. Unqualified `§` references point into `plan-approval.md`; `step N` refers to this file's list.

## Browser gate

1. Probe `printenv CLAUDE_CODE_REMOTE`; `true` → return `fallback` and `rm -f` the served copy if one exists.
2. **Figures** (first launch only, re-authored after a figure comment, a rewrite, or an out-of-gate plan edit): write `<slug>.figures.md` as `## <section name>` blocks matching plan headings, plus an optional `## Hero` block rendered above the plan; one figure and a one-sentence caption per block, at most three besides Hero. Every label and number comes from the plan. A mermaid fence for a flow, a sequence, or a dependency graph; inline SVG for a position on an axis, a grid of records, or two rows compared. `node "<base dir>/scripts/plan-review/figures-check.mjs" --template` prints both shapes with the palette a figure may use; text over a filled shape takes the foreground named for that fill. Then run it with `--plan <plan> --figures <figures file>` and fix each line it reports; a block still reported after two fixes is removed.
3. **Compose**: if the served copy exists, `cp` it to `.plan-review.prev.md`. Write the served copy = canonical plan with figure blocks inserted (after Overview's bullets, before a Decision's first `**Question**`, before Build order's list, after a prose section's last sentence).
4. **Launch** in background Bash, with a status line in the same turn:
   `node "<base dir>/scripts/plan-review/serve.mjs" --plan ".claude/plans/<slug>.plan-review.md" --lang <language> --wait`, adding `--prev ".claude/plans/<slug>.plan-review.prev.md"` when that file exists, and `--port <n> --no-open` when a `.url` file from an earlier launch of this run gave a port (read it, then `rm -f` it first). Never pass `--timeout`. In the next turn read the `.url` file (up to 2 retries) and show the URL in one line on the first launch or when the port changed. In a wait from `SKILL.md` Phase 5 (Plan Approval) step 2, a chat reply its step 3 would class other than **Anything else** stops the viewer (its launch command plus `--stop`, exit ignored) and returns `fallback` with that reply. Answer the rest, pointing other requests to the page; keep waiting.
5. **Read the result** when the process exits: the one-line submit JSON on stdout, `{"decision": "approve" | "revise", "branch": "stay" | "new" | "stack" | null, "comments": [{"block", "section", "excerpt", "kind": "prose" | "figure", "body"}]}`. No JSON by the exit marker after 5 re-reads → `fallback`, unless the exit is non-zero, step 4 did not stop it, and the previous launch did not also exit non-zero without JSON: then relaunch per step 4. When `branch` is set and differs from the Branch section's Recommendation, swap the two in the plan and the served copy.
6. **approve** → return `approve`; comments are advisory.
7. **revise** → apply every comment first: `prose` to the plan, `figure` and the `_hero` block to the figures file. Answer questions, apply change requests, locate blocks by `excerpt`. A comment on the Branch card (`section` `branch`) asking to work on another branch → return `wrong-branch` after recording the replies. Record each reply in `<slug>.plan-review.thread.json`, which the viewer owns: never create it — read it, fill the matching entry's `reply` and `disposition` (`answered` / `revised` / `both`), and write it back with the top-level `rounds` array and every entry's `id` / `block` / `anchor` intact. Then: an approach-level change → return `rewrite-approach` (the plan already carries the edits); otherwise re-compose and relaunch (step 3). No iteration cap; Plan Review is not re-run for localized edits.
