# Interactive commits

Read from `SKILL.md` Phase 14 (Interactive Commits), Phase 15 (Update Rules), and Phase 16 (PR Rule Extraction). Unqualified `§` references point into this file. Every line shown to the user is in the resolved language; subjects, bodies, paths, and diffs stay verbatim.

## Approval tokens

Judge replies semantically; the phrases are examples, not matchers. **accept**: OK / approve / next / LGTM / コミットして / 進めて. **adjust**: a concrete change request (subject wording, move a file, split or merge). **cancel**: stop / abort / やめる / 中断. A question or non-committal reply is not approval: re-present and ask. Every gate names at least one short accept word so brief replies work.

## Procedure

1. **Branch sanity.** `git merge-base --is-ancestor <base-commit> HEAD` must exit zero; otherwise stop and report.
2. **Default-branch guard.** Resolve the default branch: `git symbolic-ref -q --short refs/remotes/origin/HEAD` minus `origin/`; if that fails, the `HEAD branch:` line of `git remote show origin`; if both fail, say the guard was skipped and continue. If `git rev-parse --abbrev-ref HEAD` equals it, `git switch -c <task-slug>` (on a name clash append `-2`; a second failure stops). If the user then asks to stay on the default branch, switch back, note the choice, and continue.
3. **Collect changes.** `git status --porcelain=v1 --untracked-files=all -z`, once. Drop `SKILL.md` § Workflow artifacts. Empty → mark the phase completed. Otherwise this list is the roster.
4. **Deduce style.** `git log -n 10 --format=%s`; match its type prefixes and mood.
5. **Stashing-hook question (USER GATE)** — only when the plan below has two or more groups and `test -f "$(git rev-parse --git-path hooks/pre-commit)"` exits zero (probe once per run). Landing one group leaves the others unstaged; a hook that stashes, reformats, and reapplies unstaged changes can lose them. Offer two roads and wait: **suppress the hook** — when `lefthook.yml` exists at the repo root the prefix is `LEFTHOOK=0`, otherwise ask the user for the prefix their hook manager documents; apply it to every `git commit` this run issues, including rule commits; **proceed unchanged** — for a hook that stashes nothing. `cancel` ends the phase; anything else re-asks.
6. **Commit plan (USER GATE).** Two paths, decided by whether `refs/dev-workflow/<slug>` exists after absorption.
   - **Chain path**: the plan is the chain's commits in order (`git rev-list --reverse <base-commit>..<tip>`), one per Build order step with its heading as the draft subject, plus the trailing review-fixes commit when absorption left one. Present a numbered list of subject plus `git diff --stat <parent> <commit>` per entry. `adjust` here is a closed list: reword a subject or body; merge adjacent commits (the later commit's tree is landed under one message and the earlier is skipped). Moving a file between commits or splitting one is not offered; the user may ask to drop the chain, which switches to the cohesion path below over the whole diff. In mob mode the entries also carry the reviewed-state label and the already-reviewed accept variant of `mob-mode.md` § Commits.
   - **Cohesion path** (no chain): group the roster by cohesion; one commit is the usual case. Release bookkeeping (version bump, CHANGELOG) is its own group. When the change spans separable layers (backend endpoint and its test, a frontend wrapper, the UI consumer), offer the layer split as an alternative. Groups are file-disjoint. Present a numbered list of subject plus paths. `adjust` regroups and re-presents.
   On either path: if `git diff --cached --name-only` is non-empty, say pre-run staging will be discarded. Wait. `cancel` ends the phase.
7. **Per commit, in order.**
   - Prepare the commit's content. Chain path: stage nothing yet; the diff to present is `git diff <commit>^ <commit>`, and the tree is landed at accept time in one call. Cohesion path: `git add -- "<p1>" "<p2>"`. Never `-A` or `.`.
   - With `commit_review_gate: crit` and crit available (§ Crit gate), review in the browser instead of the chat presentation below; a `true` verdict is **accept**, comments feed **adjust**, and a broken crit run falls back to the chat presentation for that commit only.
   - In mob mode, a `changed since review` commit under the already-reviewed variant is presented on its post-review delta (`git diff <S_k> <commit>`) instead of the full diff, per `mob-mode.md` § Commits.
   - Present five elements: **Subject** in its own fenced block; **Body** in its own fenced block, `(no body)` inside the block when empty; **Files**, one `- <path>` per line; **Check / Test**: one line (`all checks passed and tests passed`, or the actual results, or `skipped`); **Diff**: `git diff <commit>^ <commit>` on the chain path, `git diff --cached` on the cohesion path, verbatim up to 100 lines, otherwise the first 100 lines per file with `… [N lines omitted]`.
   - Wait (USER GATE). **accept** → chain path: `git read-tree <commit>^{tree} && git commit -m "<subject>" -m "<body>"` as one Bash call, so nothing staged between the gate and the commit rides in (each commit's parent tree equals what the previous landing left in HEAD, so the landed diff is exactly that step's); cohesion path: `git commit -m "<subject>" -m "<body>" -- "<p1>" "<p2>"`. On zero exit, `landed_count += 1`. On non-zero exit, retry that command once after a short pause; on a second failure, restore the index (`git read-tree HEAD` on the chain path, `git reset -- <paths>` on the cohesion path), report `commit-failed (<last stderr line, ≤ 80 chars>)`, and end the phase. Never force, rebase, amend, or reset to recover. **adjust** → for the subject or body, update and re-present; for regrouping (cohesion path) or merging adjacent commits (chain path), restore the index as above, rebuild the remaining entries, re-present the plan with landed commits shown as history; a request that would change an already landed commit is refused with that reason and offered as a follow-up commit. If the user edited a file in the group during the gate: on the cohesion path re-present with the new diff, and behavioral edits require an explicit `continue` or `stop` (`continue` records the paths for the phase's post-commit verification); on the chain path the commit object cannot change, so say the edit will land in the post-commit extra commit and continue. **cancel** → restore the index as above, keep landed commits, leave the rest in the tree, report `<N>/<total> commits landed`, end the phase.
   - If a pre-commit hook modified files, ask once: `fold` (`git add -- <those paths>` then `git commit --amend --no-edit`; `landed_count` unchanged) or `defer` (leave them for a later group). A second hook modification on the same commit ends the phase with `pre-commit hook unstable`.
8. After the last group, mark the phase completed. Landed commits are never rewritten.

## Crit gate

crit (https://github.com/tomasz-tomczyk/crit) is a locally installed browser diff reviewer. Probe once per run: `crit --version` and `printenv CLAUDE_CODE_REMOTE`. If crit is missing or the session is remote, the whole run uses the chat presentation with one note (the install URL, or "no local browser").

Per commit: on the chain path the candidate is the chain commit itself and `<parent>` = `<commit>^` (not HEAD, whose re-created commits are not the chain's ancestors), or `<S_k>` when mob mode presents the post-review delta. On the cohesion path `<parent>` = `git rev-parse HEAD`; build the candidate without landing: `git write-tree` on the staged group, then `git commit-tree <tree> -p <parent>` with the subject and body on stdin. Then attach the **story**, because the browser shows the subject only and never the body:

1. `crit story --range <parent>..<candidate> --prep /dev/stdout` lists the hunks; each `--- (<file_path>, <old_start>) [<status>]` line is one hunk id (`old_start` is `0` for a new file).
2. `crit story --range <parent>..<candidate> --story-file - --refresh --no-open <<'STORY' … STORY` ingests crit's JSON: `prologue` (`title` = the subject trimmed to 48 chars, `overview` and `key_changes` from the body, `risks` from what the body flags, `diagram` `""`), `chapters` grouping hunks by theme (one or two per commit, each with `id`, `title`, `summary`, `hunk_refs`), and `support` for mechanical hunks (lockfiles, generated output, version bumps) with a `reason`. Every hunk goes in a chapter or in `support`; prose follows the resolved language. Reuse the first round's wording on later rounds while the subject and body are unchanged; re-derive only `hunk_refs`.

A story failure is non-fatal: a non-zero exit is retried once, an `{"ok":false, …}` rejection is not retried, and `"auto_repaired": true` is not a failure. On failure say so in one line with the last stderr line (≤ 80 chars) and launch without the story.

Run `crit --range <parent>..<candidate>` in background Bash with a status line. When either attempt of the story ingest printed `Started` or `Restarted crit daemon at <url>` on stdout or stderr, add `--no-open` to the `crit --range` command and put that URL in the status line. On exit read stdout and stderr for the literal line `approved: true` or `approved: false` (both exit 0). `true` → land per § Procedure's accept. `false` with no comments → same candidate, new round. `false` with comments → apply the `scope: "line"` comments as edits (or refuse the ones that would change a landed commit), run `check_commands` once if anything changed, then treat each `scope: "review"` body as a typed reply through § Approval tokens (cancel wins over adjust over accept); the commit stays pending and is rebuilt and re-reviewed. No parseable line or a non-zero exit → chat presentation for this commit only; crit stays enabled for the next.

## Rule commit gate

Used by Update Rules and PR Rule Extraction. Paths = `git status --porcelain=v1 --untracked-files=all -z` filtered to the rule output directories, minus `SKILL.md` § Workflow artifacts. None → skip. Otherwise stage them, present the five elements of § Procedure's per-commit presentation (Subject / Body / Files / Check / Test / Diff) with each file labeled by class — rule (`.md` in the rules dir), example (`.examples.md`), or unreviewed staging candidate (`.staging.local.md`, normally promoted on a later observation rather than committed as-is) — and a subject in the deduced style. **accept** → commit with the same pathspec form. **adjust** → narrow the pathspec by omitting paths (never `git checkout` them) or reword, re-present. **cancel** → `git reset -- <paths>`, leave them uncommitted. `landed_count` does not change here.
