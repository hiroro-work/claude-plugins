When either probe fails, skip that read entirely, present the diff in chat as the `diff` branch does, and emit **one** informational note for the whole of M11 — not per commit — in the resolved `language`: `crit --version` failed → name the install URL (<https://github.com/tomasz-tomczyk/crit>); only the reachability probe failed → name that no local browser is reachable; both failed → name the unavailability. **Already-reviewed skip option (commit-plan gate)**: at the **commit-plan approval gate** — `../dev-workflow/references/interactive-commits.md` § Propose commit plan, where that Procedure presents the numbered group list and waits — offer the junior a way to skip crit for the commits whose content they already reviewed at M6. Extend that gate from here: § Propose commit plan itself does not present the option, and only that file's § Per-commit loop carries the carve-out that admits it.

**Offer the option only when all three hold.** (1) `commit_review_gate` resolves to `crit`. (2) Both crit probes cleared — reuse the `crit_commit_review_available` the **Diff surface (`commit_review_gate` branch)** paragraph above cached at M11 entry, and run no probe of your own. (3) The plan being proposed carries at least one group whose `tree source` is a boundary object (`../dev-workflow/references/interactive-commits.md` § Propose commit plan's **Chain present** path). Whichever condition fails, present the gate exactly as `interactive-commits.md` writes it and reset `m11_crit_skip_reviewed` to `false`.

**What the option adds**: name which of the listed commits it would cover, then offer one further way to accept alongside the plain one — approve the plan **and** skip the crit review for those commits, since the junior reviewed them while they were being written. Leave out of that coverage any group `../dev-workflow/references/interactive-commits.md` § Propose commit plan's **Plan-scope cross-reference** paragraph has already stripped a path from **and every group after it**, since a stripped group moves the rest of the chain onto the pathspec derivation with it and all of them go to crit whatever the reply is. Judge the reply per [`inline-defs.md`](inline-defs.md) § (e)'s **Approval token closed list** bullet unchanged: this is a **variant of that list's `accept` bucket, not a fifth bucket**. A plain accept sets `m11_crit_skip_reviewed = false` and an accept carrying the skip request sets it `true`; only an accept writes the variable.

**`m11_crit_skip_reviewed`**: `false` at M11 entry; written by the offer-condition check above, which resets it to `false` whenever one of the three conditions fails, and by a reply to the commit-plan approval gate, so a `Mid-loop adjust` branch that rebuilds the plan and re-presents that gate overwrites it with that round's evaluation and reply; read once per commit at the application below. M11-local, like the `m6_*` variables [`diff-review.md`](diff-review.md) declares — **not** a `SKILL.md` § Cross-step state variables member.

**Where the skip applies**: at `../dev-workflow/references/interactive-commits.md` § Per-commit loop sub-step `a`'s **Diff-review mode branch**, skip crit for a commit when **both** hold — `m11_crit_skip_reviewed` is `true`, **and** this commit's group obtained its tree **from a boundary object** (that sub-step's **From a boundary object** derivation). Skipping means this commit takes the `diff` branch end to end: no crit launch, no read of `../dev-workflow/references/crit-commit-review.md`, its Diff element rendered in chat as that branch renders it, and sub-step `b`'s ordinary accept gate. The "point of this diff" note goes out as it always does.
